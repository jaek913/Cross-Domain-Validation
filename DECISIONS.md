**2026-06-28 — Phase 2 data provenance: verified hybrid, identity-checked not assumed.** The author flagged that several raw files in the shared store (`C:\Users\jaek9\Documents\LaggingTruth\Data`) were downloaded more than once with slight variants, and that the rebuild must use the exact data the Stage-1.5/1.6 verification ran on. Resolved by reading the data-loading of the original `repro_*.py` scripts (which inputs, which filenames, which parsing) and matching every candidate file against the recorded reproduction anchors — obs counts and recorded MD5 prefixes — then fetching the inputs that do not persist on disk fresh in a sandbox to confirm they reproduce the anchors before committing to them. **Result — five inputs REUSED from the store (confirmed exact):** USGS Colorado `08158000.txt` → `usgs_08158000.rdb` (46,767 valid daily obs, 1898-03-01..2026-03-18); USGS Ohio `03294500.txt` → `usgs_03294500.rdb` (35,862 obs, 1928-01-01..2026-03-18); ILINet `FluViewPhase2Data/ILINet.csv` (MD5 `d2922245…`, 1,484 National weeks 1997w40..2026w09 — the pre-truncated *used* data; byte-identical across all four Lagging-Truth papers, confirming it is the project's canonical pinned ILINet); NREVSS pre-2015 `ICL_NREVSS_Combined_prior_to_2015_16.csv` (MD5 `04445b64…`, matches the recorded hash; static pre-2015 strain counts); NREVSS post-2015 `ICL_NREVSS_Public_Health_Labs.csv` (MD5 `0120a7ae…`, right window 2015w40..2026w09 — a lightly CDC-revised version of the recorded `3700761f…`, accepted because strain subtype counts are reported as-regenerated under the pinned allocation spec, not as fixed magnitudes). **Two inputs FETCHED FRESH because the store lacks the verification's product:** (a) NOAA — the store's CDO bulk orders (`4264574-NOAA SF MA NY PA CA.csv`, `4264594 - NOAA CT TX.csv`) are the WRONG product: Blue Hill 48,520 TMAX&TMIN obs vs the anchor 51,544 (the order starts 1893, the verification file starts 1885-02-01), Dallas starts 1948 not 1953-04-26, and the orders end 2026-03-15/16 not 2026-03-18 — reusing them would have silently corrupted the weather results, so the six NCEI by-station access CSVs (`https://www.ncei.noaa.gov/data/global-historical-climatology-network-daily/access/<ID>.csv`) are fetched fresh and truncated to DATE≤2026-03-18; a fresh fetch reproduces all six counts to the day (NYC 57,413 / Blue Hill 51,544 / SF 38,366 / Philly 31,146 / Dallas 26,625 / Norwich 22,636). (b) SILSO yearly — the store holds only daily `SN_d_tot_V2.0.csv`, but the divergence operator runs on the yearly series, so `silso_yearly.csv` (`SN_y_tot_V2.0`) is fetched fresh from `https://www.sidc.be/SILSO/INFO/snytotcsv.php` and reproduces ρ = −0.230 (perm-z −3.94, std(3)−std(11) vs future Y(t+5), year≤2008 filter). **DESIGN manifest unchanged** — the yearly-SILSO call in `DESIGN.md` v0.2 is confirmed correct (the original `SOURCES.md`'s monthly `SN_m_tot` served the now-CITED Paper-4 decomposition import, not the regenerated divergence sign). `data/pull.py` enforces this provenance on every run: it identity-checks each input against its anchor and ABORTS on mismatch, so a duplicate-download variant can never silently enter. Raw data is not committed (project-local store `C:\Users\jaek9\Documents\LaggingTruth\Cross-Domain-Validation`, backed up separately); only `data/SOURCES.md` (generated by `pull.py`) is committed.
